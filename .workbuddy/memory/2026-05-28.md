## Clash 代理根因修复

### 问题
- 用户终端和浏览器均无法启动/访问 Dashboard
- 根因：Clash 代理 `127.0.0.1:59943` 通过环境变量 `http_proxy`/`https_proxy` 注入，**所有 HTTP 客户端**（requests、httpx）都走代理
- `requests` 库默认读取 env 中的 proxy 设置，包括对 `127.0.0.1:8050`（Dashboard）和 `127.0.0.1:8000`（API）的请求
- `httpx.AsyncClient` 也默认从 env 读取 proxy 设置

### 修复
1. **Dashboard `_api_get`/`_api_post`**：添加 `proxies={"no_proxy": True}` 参数绕过代理
2. **所有 `httpx.AsyncClient`**：全局添加 `proxy=None` 参数（覆盖 11 处创建点）
3. **启动脚本**：`os.environ["no_proxy"] = "localhost,127.0.0.1,0.0.0.0"` 额外设置
4. **一键启动脚本**：`scripts/start.sh`（chmod +x），全栈启动并显示正确 URL
5. **Dashboard URL**：所有 localhost 引用改为 `127.0.0.1`（避免 DNS 被代理劫持）
6. **CoinGecko**：添加 `BTC→bitcoin` 映射；Agent 监控循环添加 1.2s 请求间隔防 rate limit

### 验证
- 57/57 单元测试 ✅ | Agent paper 启动 ✅ | Dashboard HTTP 200 ✅ | 全部 httpx proxy=None ✅

## Dashboard K 线图回调修复

### 问题
- Dashboard 加载成功，但右侧 Errors 面板显示 **10 次 `Callback error updating kline-chart.figure`**
- K 线图区域空白，只有坐标轴

### 根因
- `make_subplots(specs=...)` 中 rows 2/3/4 用了 `[None]`，而 Plotly 的 `None` 表示"跳过该位置不创建 subplot"
- 导致 `fig.add_trace(..., row=2, col=1)` 时抛出 `ValueError: No subplot specified at grid position (2, 1)`

### 修复
- `specs` 中的 `[None]` → `[{}]`（空 dict 表示创建默认 subplot）
- 整个 `update_kline_chart` 回调外加 `try/except`，任何异常返回 graceful fallback figure

- 57/57 单元测试 ✅ | Dashboard import ✅ | K-line callback 注册 ✅ | Python syntax ✅
